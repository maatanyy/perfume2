# 가격조사 엑셀 개편 + 쿠폰가 크롤링 설계

날짜: 2026-07-04
상태: 사용자 승인됨

## 배경 / 목표

현재 크롤링 결과 엑셀은 제품마다 제목 블록이 세로로 반복되는 구조라 가격 비교가 어렵다.
또한 "상품 가격"이 쿠폰 적용 후 가격 하나로만 수집되어 판매가와 쿠폰 할인 폭을 알 수 없고,
품절 상품이 눈에 잘 띄지 않는다.

**목표:**
1. 엑셀을 플랫 테이블(행 단위) 구조로 개편해 필터/정렬/비교가 쉽게 한다.
2. 각 행에 제품명이 들어가도록 한다.
3. 가격을 판매가 / 쿠폰율 / 쿠폰적용가로 분리 수집한다.
4. 품절을 엑셀에서 즉시 알아볼 수 있게 한다.

**제약:** DB(users, crawling_jobs, crawling_logs)는 스키마·데이터 모두 변경하지 않는다.
기존 가입 사용자와 작업 이력이 보존되어야 한다.

## 범위

변경 대상:
- `crawlers/base_crawler.py` 및 사이트별 크롤러 5개 (ssg, cj, shinsegae, lotte, gs)
- `utils/crawling_engine_v2.py`의 `_save_results()` (엑셀 생성)
- 크롤러 단독 검증용 테스트 스크립트 (신규)

변경하지 않는 것:
- DB 모델/스키마 전부
- 웹 UI(템플릿, JS), SSE 진행률 스트림, 라우트
- 크롤링 엔진의 배치/스레드/세마포어 구조
- 구글 시트 읽기(`utils/google_sheets.py`)

## 1. 크롤러 반환 스키마 확장

`extract_price()` 반환 dict에 필드를 추가·분리한다.

| 필드 | 의미 |
|---|---|
| `판매가` | 쿠폰 적용 전 판매 가격 (int 또는 None) |
| `쿠폰적용가` | 비로그인 페이지에 공개 표시되는 쿠폰/혜택 적용가 (int 또는 None) |
| `상품 가격` (기존 유지) | 대표가 = 쿠폰적용가 ?? 판매가. SSE/로그 하위호환용 |
| `배송비`, `배송비 여부` | 기존과 동일 |
| `최종 가격` | (쿠폰적용가 ?? 판매가) + 배송비 |
| `결과 상태` | success / sold_out / not_found / error (기존 유지) |

- 쿠폰율은 크롤러가 저장하지 않고 엑셀 생성 시 `(판매가-쿠폰적용가)/판매가`로 계산한다.
  (판매가·쿠폰적용가가 모두 있고 쿠폰적용가 < 판매가일 때만 계산, 그 외 "-")
- 사이트별로 판매가 선택자와 쿠폰가 선택자를 분리해 추가한다. 구현 시 실제 상품
  페이지에서 선택자를 검증한다.
- 쿠폰가가 비로그인에 노출되지 않는 사이트는 `쿠폰적용가=None`으로 두고 판매가만 채운다.
- GS 크롤러는 현재 `결과 상태` 키가 누락되어 있으므로 함께 통일한다.

## 2. 품절 감지 강화

현재는 Selenium alert 문구/에러 키워드로만 품절을 감지해, 페이지에 "일시품절" 뱃지만
표시되는 경우 `not_found`로 잘못 분류된다.

각 크롤러 `extract_price()`에 본문 품절 감지를 추가한다:
- 품절 표시 요소 선택자(품절 버튼/뱃지) + 텍스트 키워드(품절, 일시품절, 매진, SOLD OUT 등)
- 가격 추출 실패 + 품절 표시 발견 → `결과 상태 = "sold_out"`
- 가격이 정상 추출되면 품절 표시가 있어도 success (일부 사이트는 옵션 품절 문구가 상시 존재)

## 3. 엑셀 개편 (`_save_results` 재작성)

### 시트1 "전체 결과" — 플랫 테이블

컬럼 순서 (확정):

```
제품명 | 판매처 | URL | 판매가 | 쿠폰율 | 쿠폰적용가 | 배송비 | 최종가격 | 상태 | 비고
```

- 헤더 1행, 이후 모든 행이 데이터. 같은 제품의 판매처 행들이 연속 배치된다.
- 헤더 틀 고정(freeze panes) + 자동 필터(autofilter) 적용
- 판매처: `Waffle (우리회사)` / `경쟁사 (이름)` (기존 표기 유지)
- 상태 표시: `판매중` / `품절` / `추출실패` / `오류`
- 서식:
  - 품절: 행 전체 빨간 배경 강조 + 가격 셀에 "품절" 명시
  - 추출실패: 주황 텍스트, 오류: 빨간 텍스트 (기존 색 체계 계승)
  - 숫자 컬럼은 숫자 타입으로 기록(천 단위 콤마 서식), 값 없으면 "-"
  - 쿠폰율은 % 문자열(예: "10%") 또는 "-"
- 비고: 에러 메시지/품절 사유 (최대 100자)

### 시트2 "가격 역전 항목"

- 시트1과 동일한 플랫 컬럼 + `가격차이` 컬럼
- 역전 판단: **최종가격**(배송비 포함) 기준, 경쟁사 최종가 < Waffle 최종가
- 역전 발생 제품의 Waffle 행 + 더 싼 경쟁사 행만 수록
- `가격차이`: `-N원 저렴` (빨간 굵은 글씨, 기존 표기 유지)
- 역전 항목 없으면 "가격 역전 항목이 없습니다." 한 줄

## 4. 예외 처리 규칙

| 상황 | 판매가 | 쿠폰율 | 쿠폰적용가 | 최종가격 | 상태 |
|---|---|---|---|---|---|
| 정상 + 쿠폰가 노출 | 값 | 계산값 | 값 | 쿠폰가+배송비 | 판매중 |
| 쿠폰가 노출 안 됨 | 값 | - | - | 판매가+배송비 | 판매중 |
| 쿠폰가만 발견 | - | - | 값 | 쿠폰가+배송비 | 판매중 |
| 품절 | 품절 | - | - | - | 품절 |
| 추출 실패 (not_found) | - | - | - | - | 추출실패 |
| 오류 (error) | - | - | - | - | 오류 |

- URL이 시트에 없는 판매처도 행을 만들어 "오류 / URL 없음"으로 기록 (기존 동작 유지)

## 5. 하위 호환성

- SSE 진행률(`_push_item_progress`)과 크롤링 로그는 `상품 가격`(대표가)을 계속 사용
  → 웹 화면 변경 없음
- `CrawlingJob.result_file` 등 DB 필드 사용 방식 동일
- 기존에 생성된 결과 엑셀 파일은 그대로 두며, 새 형식은 새 작업부터 적용

## 6. 검증

1. 크롤러 단독 테스트 스크립트: 사이트별 실제 상품 URL 1~2개로 판매가/쿠폰적용가/품절
   추출 결과를 출력해 확인 (판매중 상품 + 품절 상품 각각)
2. 소량(2~3개 상품) 구글 시트로 전체 잡 실행 → 생성된 엑셀을 열어 컬럼 순서, 서식,
   품절 강조, 역전 시트를 육안 확인
3. 기존 사용자/작업 이력이 그대로인지 확인 (DB 무변경 확인)
